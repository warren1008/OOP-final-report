# 斷線機制驗證紀錄

日期：2026/11/04。環境：本機 Windows、Oracle JDK 25.0.2，使用 UTF-8 與 `--release 17` 編譯。無外部依賴。

## 實際執行

`test.cmd`：13 個情境、55 項斷言通過。各情境透過真實 loopback Socket 執行，GUI 情境使用真正的 Swing 元件；測試來源位於 `tests/DisconnectTests.java`。逐項輸出保存於 `test-results.txt`。

1. 單人加入不會直接判勝。
2. 三人中一人 EOF 離線，仍有兩人存活時對局繼續；第二人 RST 離線後，Server 才判剩餘玩家獲勝。
3. TCP 半關閉會正確觸發 EOF 清理。
4. 持續接收快照、但不回傳心跳的 Client 會被 Server 逾時移除。
5. 全部離開後重設新局，新加入單人不會沿用舊勝負。
6. 深層複製快照不受外部蛇身或食物清單修改影響。
7. 拒絕連線時 GUI 顯示特定提示、只顯示一次，EDT 可回應。
8. GUI 收到三人減兩人的通知後仍可操作；最後只剩自己時顯示 Server 的勝者 ID，並停止操作。
9. Server 中斷時顯示連線中斷，不產生虛構勝利；讀寫錯誤及逾時不會重複提示。
10. Server 不送握手回應時有加入逾時，不會永久卡在 ObjectInputStream。
11. 已握手、但不再送出任何訊息的 Server 會被 Client 偵測為失聯。
12. 重新連線按鈕能從拒絕連線、Server 重啟恢復，舊回呼不覆蓋新連線狀態。
13. 使用正式 10 秒門檻的真實 Socket 逾時測試。

正式 Server 逾時量測約 10.1 秒，數值保存在 `test-results.txt`；最新正式 Client 無回覆逾時擷取量測為 10,138 ms，保存於 `capture-results.txt`。這些是本機該次量測值，不是跨機網路延遲保證。

## 實際介面擷取

`capture.cmd` 已完成五種情境。`screenshots` 每個情境各有提示視窗及 `-full` 完整介面 PNG：

| 檔案前綴 | 觸發方式 | 檢查結果 |
|---|---|---|
| 01-connection-failed | 連到沒有 Server 監聽的本機埠 | 顯示連線失敗及檢查 IP／Port 提示 |
| 02-server-disconnected | Client 加入後關閉真正的 Server | 顯示 Server 連線中斷，停止輸入 |
| 03-player-left-continues | GUI 與另外兩個真實 TCP Client 加入，再關閉一人 | 顯示仍有兩名存活玩家，對局繼續 |
| 04-last-survivor | 再關閉另一位玩家 | 顯示 Server 判定剩餘玩家獲勝 |
| 05-server-timeout | 測試 Server 完成握手後刻意不再回覆 | 正式 10 秒 Client 門檻觸發，顯示無回應提示 |

圖片由實際 Swing 元件的 `printAll` 匯出，並非重繪的介面示意。多人斷線擷取暫將移動 Tick 延長，以穩定重現網路情境；連線、事件、清理與勝負仍走同一套正式程式。無回覆 Server 使用測試替身，Client 則使用正式 2 秒 PING／10 秒門檻。
